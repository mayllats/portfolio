Project 01 Arc — 2025–2026

Arc Design System

A multi-tenant fintech design system, built from zero — brand identity, components, and product flows, together.

Challenge
Process
Decisions
Outcome
Challenge

Arc launched with no visual identity, no component library, and no established design language. The product itself was still being defined — PRDs arrived in iterations, and every foundational choice had to hold up across a scope that kept expanding, as the sole designer responsible for brand, system, and product at once.

Process

I architected the system for multi-tenant deployment from day one — separating the token layer from component logic, and organizing everything into Global, Player-facing, and Admin layers, each independently skinnable.

Key decisions
01
Token-based theming, not duplication — a new operator rebrands through a token swap, never a component rebuild.
02
Claude as a technical execution partner, used directly through the Figma MCP connector for component architecture decisions and plugin-driven design system work — not just early ideation.
03
Evolution treated as part of the system, not a failure of v1 — three refactor passes before calling the foundation stable.

Project 02 Accountfy — 2024

Currency Selector in Cashflow

Multi-currency treasury management, designed so finance directors never lose track of where a number came from.

Challenge
Process
Decisions
Outcome
Challenge

Accountfy's cashflow module handled multiple currencies, but the existing interface buried conversion context behind manual lookups. Finance directors managing international operations needed to compare values across currencies without losing track of the underlying exchange rate or which figures were already converted.

Process

I mapped how finance teams actually scan a cashflow view — from totals to line items and back — and tested currency-switching patterns that kept that scanning order intact instead of forcing a full reload or a modal interruption.

Key decisions
01
Inline switching, not replacement — the original entry stays visible next to the converted value, so the source of a number is never ambiguous.
02
A persistent rate indicator, not a tooltip — the exchange rate is decision-relevant information, not a footnote.
03
View-scoped currency, not account-scoped — comparing two markets never requires leaving the screen.

BaaSWhite LabelDesign Systems
Challenge

Own's BaaS platform served multiple partner companies, each needing its own visual identity layered over the same underlying banking infrastructure. Too much freedom and the experience fragments into inconsistent, hard-to-maintain interfaces; too little and the platform stops feeling like the partner's own product.

Process

I led the move from hard-coded styles to a token-based architecture — separating what a component does from how it looks, so brand identity became a configuration, not a redesign.

Key decisions
01
Semantic tokens between primitives and components — a partner's color, type, and spacing choices propagate everywhere automatically.
02
A constrained customization surface — logo, palette, typography, a few layout variants — kept ownership without opening the door to usability regressions.
03
Documentation lived next to components in Storybook, so engineering could ship new brands without designer involvement for routine cases.

Project 04 Own Financial Services / Paketá — 2022

Balance Unification App

One coherent financial picture, built from accounts that were never meant to talk to each other.

Challenge
Process
Decisions
Outcome
Challenge

Users held several financial products under the same umbrella — checking, savings, business accounts — but each lived in its own silo, with its own balance and its own transaction history. The mobile experience needed to unify them without pretending the underlying complexity wasn't there.

Process

I worked from real transaction data to design a hierarchy that prioritized the number people actually wanted first — total available balance — while keeping each account's identity legible underneath it.

Key decisions
01
One unified balance up top, with individual accounts always one tap away — never hidden behind a menu.
02
Transactions tagged by account of origin, not merged into an undifferentiated feed, so users could still reason about where money moved.
03
Visual weight reserved for amounts and names — icons and metadata recede so the numbers read first.

Low-codeAutomationSaaS
Challenge

Nextel and Santander needed to configure complex business rules and campaign logic without filing a ticket with engineering every time a rule changed. The interface had to make conditional logic — branches, thresholds, exceptions — legible to people who had never written a line of code.

Process

I treated the canvas itself as the documentation: instead of abstract form fields, the workflow builder represented logic as a visual graph that mirrored how business users already described their own rules out loud.

Key decisions
01
Plain-language conditions, not technical operators — lowering the barrier for non-technical configuration.
02
Inline validation while building, catching contradictory branches before publish instead of failing silently in production.
03
A canvas built for density — scaling from a five-step rule to a sprawling decision tree without losing legibility, since dense flows were the norm for these clients.
